SECTION 2b — Ustruct: unauthorized versions PRESENT in the structures opened
====================================================================================================
WHY THIS TABLE EXISTS, AND WHY THE ONE ABOVE CANNOT BE READ WITHOUT IT.

§4.6 S5: "A zero count is not conclusive. It proves only that nothing unauthorized crossed
THE POINT WHERE THE INSTRUMENT SITS ... an instrument written into a WHERE clause is
STRUCTURALLY INCAPABLE of observing" index entries scanned before that point.

This probe's counters are SQL functions. They fire at ROW ACCESS, after SQLite has already
used the indexable terms to bound the seek. So U1 -- INDEX-ENTRY READS -- IS NOT
INSTRUMENTABLE through node:sqlite, and no zero above should be read as covering it.

Ustruct is placement-independent: it counts unauthorized versions PRESENT in the structures
the traversal opens. It cannot be moved by moving an instrument.

THE FINDING THIS TABLE CARRIES, stated plainly because it decides two verdicts:
a design can report U = 0 at every collection size while the structures it opens still HOLD
unauthorized entries. The seek bound skipped them; the counter never saw them; and whether
the engine read the index entries describing them is NOT OBSERVABLE on this test subject.
§4.6 S6 requires E1 for exactly this reason -- "an in-query counter does not measure rows
scanned at all. The PLAN is the evidence for scan extent" (§4.6 S7).

satisfies the predicate", and states that "a plan showing a scan OR SEEK over a structure
