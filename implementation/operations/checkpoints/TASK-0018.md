while its child is alive — the `reason` advancing 30s → 90s → 210s in step with wall-clock is that
refresh happening. Stated as inference rather than dressed up as a process listing.

### Gate 4 — no stale `NOOP` persists: **MET**

Across the whole window observed, `decision` was never `NOOP` and `runnerActive` was never `false`.
The `head` field reads `0c7d7b2`, which equals the actual `HEAD` — the specific pair of symptoms
TASK-0017 recorded (`NOOP :: no READY task`, `runnerActive: false`, and a two-commit-old `head`
during a live run) is absent. The defect does not reproduce.

### Gate 3 — terminal heartbeat and lock release: **NOT OBSERVED — structurally unobservable here**

The terminal record is written by the supervisor **after this runner process exits**
(`supervisor.ps1` lines 468–485 and 728–729: the poll loop ends on `WaitForExit`, then `Complete-Cycle`
writes `COMPLETED` or `FAILED`). A session cannot observe the state its own exit produces. This is a
property of the arrangement, not a fault in the fix and not an observation that failed.

Where the evidence will land, and its durability:

- `logs/supervisor-20260820.log` — a `COMPLETED :: runner completed: ...` or `FAILED :: ...` line for
  `task=TASK-0018`. **Durable.**
- `state/heartbeat.json` — the terminal decision, and `state/runner.lock` removed. **Transient:** the
  next cycle, ~10 minutes later, overwrites the heartbeat with `NOOP`.

### Incidental: no `runner-TASK-0018-*.log` file exists during the run

Verified absent, and then explained rather than left as a bare anomaly. `Start-RunnerProcess` reads
both streams with `ReadToEndAsync()` and writes them to disk only after the process exits
(`supervisor.ps1` lines 460–485). Every earlier task's `.out.log` therefore appeared at its end, not
its start. **Expected behaviour of the committed code, not a regression** — but it does mean runner
output cannot be followed live, which is worth knowing before someone tails a file that will not
exist for hours. Recorded as an observation; no change proposed, and none would be authorized here.
