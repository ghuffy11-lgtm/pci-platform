### The two defects, recorded because they are the most instructive part of the run

**Both were the presence-versus-provenance error DA-4 exists to prevent — committed by the probe
written to test for it.** Both were found by **reading the probe's first output against its own stated
standard**, which is the same step that caught an insertion figure twice this week.

1. **An INGEST write was reported as a DA-1.1 finding.** The first rollback-journal section opened a
   transaction, inserted corpus rows, found the unauthorized marker in the journal, and called it
   request-induced. **It was not a request being resolved for any subject.** Under DA-4 row 1 that is
   **not a finding at all**.
2. **The backup reach verdict asserted rather than measured** — *"written wherever the caller names"*.
   **An assertion about an API is not a measurement.**

**Fixing defect 1 is what produced the run's sharpest result.** Rebuilding the section to measure both
provenances required a request-shaped write, which surfaced that **an `UPDATE` touching only authorized
rows still journals unauthorized neighbours, because journalling is page-granular** — a finding the
original design could not have reached. **It also cost an expectation: the append-shaped write
journalled nothing.**
