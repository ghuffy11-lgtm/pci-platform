
Four independent ways the heartbeat is wrong about the present moment:

1. `decision: NOOP` and `reason: no READY task` — a task was READY and was selected;
2. `runnerActive: false` — a runner had been alive for minutes;
3. `readyTask: ""` — the runner was working on TASK-0017;
4. `head: 420eabc` — actual HEAD is `d0007b0`, two commits later.

**The log is correct and the heartbeat is not.** That distinction matters: the defect is confined to
the state file, not to the supervisor's decision-making. Nothing was mis-scheduled.

### Cause — established, not guessed

`supervisor.ps1` writes the heartbeat in exactly one place: the nested `Complete-Cycle` helper inside
`Invoke-SupervisorCycle` (lines 565–572), which runs only at a cycle's **terminal** point.

When a runner is started, `Start-RunnerProcess` calls `$proc.WaitForExit()` (line 435) and **blocks
for the entire Claude session**. Between lock acquisition (line 619) and that call returning, no
heartbeat write occurs anywhere on the path. The file therefore retains the previous cycle's content
for the whole duration of the run — which for these tasks is minutes to hours.

A second, smaller defect sits alongside it: the terminal decision for a **completed** run is also
`STARTED` (line 658), with the difference carried only in the free-text `reason`. An observer parsing
the `decision` field cannot distinguish "a runner has just been launched" from "a runner finished
successfully".
