# PCI Customer Zero Architecture

## Purpose

Define the first real-world deployment used to validate PCI before external productization.

## Principle

Customer Zero is a validation environment, not a special fork of PCI. Capabilities proven there must remain productizable.

## Initial Domains

- Network
- Helpdesk
- Enterprise Knowledge
- Platform/Infrastructure
- Facilities
- Biomedical

## Validation Areas

- Identity and access control.
- Knowledge ingestion and provenance.
- Infrastructure monitoring.
- Network discovery and safe configuration workflows.
- Helpdesk context enrichment.
- Internal document retrieval.
- Cross-domain impact analysis.
- Backup and restore.
- Upgrade and rollback.
- Offline operation.

## Promotion Rule

A capability is not considered product-ready merely because it works at Customer Zero. It must be documented, tested, configurable, secure, recoverable, and deployable without organization-specific assumptions.

## Success Criteria

PCI should demonstrate that it can understand and operate against real organizational context while preserving existing system ownership and human governance.
